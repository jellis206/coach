# Coach Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a private, workstation-local observer for Claude Code, Codex and Pi that produces evidence-backed agent-improvement debriefs at wrap-up, with reproducible standalone installation and dotfiles integration.

**Architecture:** A Rust binary provides local IPC ingestion, a crash-aware on-demand daemon, SQLite storage, diagnostics and debrief queries. Native command hooks and a small Pi extension forward bounded observations without changing agent decisions. An agent-readable README and shared skill support installation and collaborative improvement without automatic uploads.

**Tech Stack:** Rust stable, clap, serde/serde_json, rusqlite with bundled SQLite, sysinfo for portable process identity, fs2 locking, uuid; std Unix sockets and bounded channels; TypeScript Pi adapter; Python 3.11 standard library for configuration merging and offline installer tests; Bun for adapter tests. Avoid adding an async runtime unless measured integration requirements justify it.

**Spec:** `docs/superpowers/specs/2026-10-26-coach-design.md`, approved in Plannotator, including the user's standalone agent-readable README requirement.

## Global Constraints

- Name: Coach; executable `coach`. No conflicting executable was found in the initial PATH check; recheck before installation.
- Rust core, SQLite WAL, macOS and Linux. No TigerFS, remote database, dashboard, telemetry, automatic background model calls or Windows claims.
- Capture prompts, arguments and bounded tool/error output by default. Default retention: 30 days. Default textual field cap: 64 KiB with explicit truncation metadata.
- All evidence, logs, exports, runtime state and debriefs remain outside repositories and dotfiles. Per-workstation data never syncs through Coach. Generalized approved improvements can be shared, evidence cannot.
- Private directories 0700, files 0600. Local Unix socket only. Reject insecure/pre-existing ownership/path situations; do not follow untrusted socket/lock symlinks.
- Preserve existing safety hooks, settings and Codex hook trust. Collection never returns allow/deny, tool mutations, model context or blocking exit codes.
- Bound queues, frames and timeouts. Report dropped/unknown data. Do not claim zero overhead or complete coverage.
- Processes, conversations, forks, nested tools and spawned agents are distinct identities. Idle/Stop does not mean work completed.
- Default process checks every 2 seconds; shutdown grace 3 seconds; bounded final drain 2 seconds. These are implementation choices adjustable after lifecycle tests, not additional public configuration knobs.
- Target warm enqueue p95 <5 ms; measure cold start separately. If unmet, report measurements before declaring low overhead.
- No public evidence fixtures. All tests use synthetic content. MIT license as approved with the design's proposed defaults.
- Commit with signed `git commit`. Check Linear tracking before commits/PRs. Current tracking does not include prospective Coach or dotfiles identities; recheck actual origin.
- No product scaffolding or repository publication until this plan is approved. Work natively in this session unless the user chooses otherwise; independent dispatch currently requires an unavailable tmux session.

## Review Focus

1. Shells between hook and harness must not be mistaken for owners; ownership ambiguity must produce a diagnostic, never an immortal daemon or fabricated identity (Task 1/3).
2. An unrelated process reusing a PID or a conversation clear/reload must not keep Coach alive or end collection prematurely (Task 3/5).
3. Existing configuration symlinks and Codex trust must survive setup/removal; registrations outside this install must remain byte-semantically intact (Task 7/8).
4. Permission prompts and business-specific output can contain secrets even after redaction; diagnostics/public improvements must not leak raw payloads (Task 2/6/7).
5. Headless no-session workers and their validators must appear once under the correct parent, or explicitly as unknown, without conflating transcript ancestry (Task 5/8).

## Task 3: Crash-aware daemon and fail-open sender

**Files:** `src/{main,daemon,process}.rs`, `tests/lifecycle.rs`, `src/event.rs` for wire message types.

**Interfaces:** `ProcessIdentity { pid: u32, started_at: u64, instance_id: String }`; `process::identify(pid: u32) -> Result<ProcessIdentity>`; `process::is_alive(identity: &ProcessIdentity) -> bool`. Versioned wire messages: `Register { owner, source }`, `Event(EventEnvelope)`, `Unregister { instance_id }`, `Ping { instance_id }`. Commands: `coach daemon`, `coach hook <claude|codex>`, `coach doctor [--json]`; hook command reads one bounded stdin payload and is always fail-open. Daemon startup and sending are shared internally, not exposed as a general remote API.

- [ ] Write failing tests for concurrent first startup, two roots, child outliving parent, dead owner/PID reuse, session change not releasing process, reconnect, shutdown-grace cancellation and stale events not renewing dead leases. Make process inspection/clock injectable only at the narrow test seam.
- [ ] Run `cargo test --test lifecycle`; confirm failure. Implement file-lock ownership, private socket creation, bounded connection handling and a 1024-event writer queue. One writer handles SQLite; socket receivers enforce size/connection limits and read deadlines.
- [ ] Implement proven owner discovery from Task 1, 2-second liveness checks, 3-second shutdown grace, 2-second final drain, reconnect and generation-aware stale registration handling. Do not kill the daemon directly from the last hook or trust PID alone.
- [ ] Add fault tests for queue saturation, disconnected/partial clients, daemon kill/restart, file lock contention, socket symlinks, SQLite lock/disk error injection and slow sender. Assert bounded memory/time, reported gaps and hook exit 0 with no decision/context stdout. Persist available delivery counters; distinguish losses that cannot be counted after an abrupt process crash.
- [ ] Run `cargo test --test lifecycle` repeatedly and a synthetic sender benchmark recording warm p50/p95 and cold startup. Check thread/socket cleanup and no self-renewing liveness; commit `feat: add on-demand Coach daemon lifecycle`.
